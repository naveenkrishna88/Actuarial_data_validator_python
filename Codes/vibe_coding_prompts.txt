Use this Master Prompt in a new AI chat before writing any code. It demonstrates how to use AI for prompt engineering, architectural validation, and breaking down a complex actuarial problem into simple, modular prompts for non-technical users.

[MASTER PROMPT - COPY & PASTE TO AI]
--------------------------------------------------------------------------------
Act as a Principal Actuarial Data Architect and AI Systems Engineer.

I am an insurance analyst with no coding background. I want to build an automated, end-to-end Actuarial Data Validator tool that will run entirely inside a Google Colab notebook.

BUSINESS CONTEXT & PROBLEM:
1. In insurance operations, we work with messy Excel datasets (specifically: Vehicle Sales Data and Warranty Claims Data).
2. Common data quality issues include: missing critical fields, duplicate identifiers, invalid dates (such as Excel serial numbers like 44629), values outside valid actuarial ranges, and cross-dataset inconsistencies (e.g., a claim filed before the vehicle was sold, or an invalid claim status).
3. Currently, checking these takes hours of manual Excel work.

WHAT I WANT TO BUILD:
An automated two-phase system using Google Gemini AI and Python:
- Phase 1 (Schema & Cleaning): The AI inspects a small sample of our raw Excel tables to generate a standardized Data Schema (data types, descriptions). We then clean the data (especially messy dates and numbers) based on this schema.
- Phase 2 (Validation Rules & Execution): The AI reads the cleaned data schema and generates an exhaustive set of validation rules (both single-table checks and cross-table checks). A deterministic Python engine then executes these rules against the full datasets and exports an audit-ready Excel report of all violations (identifying the row number, VIN, failed value, and reason).

CRITICAL REQUIREMENTS:
- Human-in-the-Loop: At key milestones (after Schema generation and after Rules generation), the pipeline must output Excel files so an analyst can review, verify, and manually tweak them in Colab before proceeding.
- No Over-Engineering: The solution must be minimal, concise, DRY (Don't Repeat Yourself), and zero boilerplate. No dummy data.
- Non-Technical Accessibility: The implementation must be broken down into clean, modular, sequential steps that a non-technical person can build using conversational "vibe coding".

YOUR TASK:
1. Review this solution architecture from an actuarial and data quality perspective. Point out any potential bottlenecks, edge cases, or improvements.
2. Break this project down into a step-by-step "Vibe Coding Roadmap" split into two distinct parts:
   - Part 1: Schema Generation & Data Cleaning
   - Part 2: Rules Generation & Validation Execution Engine
3. For each step in the roadmap, craft a precise, non-technical prompt that I can copy-paste into an AI coding assistant to generate the exact Python code for a single Google Colab cell.

### Part 1: Data Schema Generation and Data Cleaning (New Chat)

I want to build an automated Data Schema Generation and Cleaning tool in Python, specifically structured to run in a Google Colab notebook. I will be working with insurance data like Sales and Claims in Excel.

CRITICAL CONSTRAINT: The codebase must be extremely concise, minimal, and DRY (Don't Repeat Yourself). Avoid over-engineering, unnecessary abstractions, and boilerplate. Keep it simple and focused. Do not create any example or dummy data.

**Prompt 1A: Setting up the Schema Agent**
Write the Python code to accomplish the following in a Google Colab notebook:
1. Connect to Google Gemini AI using the `agno` framework to set up a Schema Agent. Ensure 'GEMINI_MODEL' comes from Colab secrets.
2. The Schema Agent must use a strict output structure (using Pydantic) to output the following fields (include these descriptions in the Pydantic Fields):
   - File Name: The name of the Excel file being analyzed.
   - Column Name: The name of the column in the file.
   - Data Type: The inferred data type (MUST be exactly one of: date, numeric, string).
   - Business Description: A description of what the column means in a business context.

**Prompt 1B: Generating the Schema**
Write the Python code for a new Colab cell to:
1. Load two Excel files (Sales Data and Claims Data) into the program.
2. Take a small sample of the data (the first 50 rows) and pass it to our Schema Agent. Ask it to figure out the data types and descriptions, and save its response to an Excel file in an "Output" folder called "Output/Data_Schema.xlsx".
3. Since this will run in Google Colab, end the current cell here so the user can use the Colab file manager to download, review, and manually edit "Output/Data_Schema.xlsx" if necessary.

**Prompt 1C: Cleaning the Data**
Write the Python code for a new Colab cell to:
1. Load the finalized "Output/Data_Schema.xlsx" and use it to clean our original data. 
2. Create a robust Date Converter function that can fix messy Excel dates (like the number 44629), handle blank values, and standardize them. 
3. If the schema says a column is a "date", run it through our converter. If it says it's "numeric", force it into a numeric format.


### Part 2: Rules Generation and Validation Engine (New Chat)

I want to build an automated Actuarial Rules Generation and Validation Engine in Python, specifically structured to run in a Google Colab notebook. I have pre-cleaned insurance data (Sales Data and Claims Data) and a Data Schema Excel file that defines the data types and business descriptions for each column.

CRITICAL CONSTRAINT: The codebase must be extremely concise, minimal, and DRY (Don't Repeat Yourself). Avoid over-engineering, unnecessary abstractions, and boilerplate. Keep it simple and focused. Do not create any example or dummy data.

**Prompt 2A: Setting up the Rules Agent**
Write the Python code to accomplish the following in a Google Colab notebook:
1. Connect to Google Gemini AI using the `agno` framework to set up a Rules Agent. Ensure 'GEMINI_MODEL' comes from Colab secrets. I need a strict output structure for this agent using Pydantic. It must output the following fields (include these descriptions in the Pydantic Fields):
   - Rule ID: A unique identifier for the rule.
   - Table 1: The primary table the rule applies to (e.g., 'Sales' or 'Claims').
   - Column 1: The primary column being validated.
   - Rule Type: The specific validation rule being applied.
   - Table 2: The reference table, if the rule involves comparing two tables.
   - Column 2: The reference column, if comparing two columns.
   - Parameter: Any specific value needed for the rule (e.g., a min/max value for 'range', or an allowed list).
   - Severity: The impact level if the rule fails (e.g., 'High', 'Medium', 'Low').
   - Description: A clear, human-readable explanation of what the rule checks.
   Critically, the Rule Type MUST be exactly one of the following 9 rules (do not create any additional rules): lookup_ref, missing, unique, positive, range, greater_than, equals, exists, allowed_values.

**Prompt 2B: Defining the Checker Functions**
Write the Python code for a new Colab cell to:
1. Create a set of 9 distinct Python checker functions that take in data columns and flag errors. These functions should directly correspond to the exactly 9 rule types defined above. 
2. Group all these 9 checker functions into a single dictionary so we can easily call them later by their name.

**Prompt 2C: Generating the Rules**
Write the Python code for a new Colab cell to:
1. Load the cleaned data samples and the Data Schema ("Output/Data_Schema.xlsx"), and send them to the Rules Agent. Ask it to generate an exhaustive list of rules. Mention to the AI that it can generate single-file rules (within a dataset) or cross-file validations (comparing between datasets). The Pydantic model defined earlier already handles the structure. Save these rules to an Excel file called "Output/Validation_Rules.xlsx".
2. Since this will run in Google Colab, end the current cell here so the user can use the Colab file manager to download, review, and manually edit "Output/Validation_Rules.xlsx" to add, modify, or remove any rules.

**Prompt 2D: The Execution Engine**
Write the Python code for a new Colab cell to:
1. Build the Execution Engine: Write a loop that goes through every single rule in the finalized "Output/Validation_Rules.xlsx" one by one.
2. For each rule, the engine should figure out which table and column it applies to, and use our dictionary of checker functions to test the entire column. 
3. If it finds any violations, it should record the row number, the exact value that failed, the rule ID, and the description.
4. Export all the broken rules and their details into a final Excel file called "Output/Validation_Report.xlsx" (with columns: Row Number, Failed Value, Rule ID, Description).
